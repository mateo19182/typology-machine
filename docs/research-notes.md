# Research notes

Archived experiments and run notes through October 13, 2026. Run IDs and counts
refer to those experiments, not a fresh installation. For current setup and service
configuration, use [deployment.md](deployment.md).

## Scripts
- `explore/coverage.py` pulls Mapillary image points and its detected objects for a city bbox.
- `explore/contact_sheet.py` random sample of Mapillary images, stratified by year and pano.
- `explore/crop_features.py` crops every Mapillary-detected object from the best image that sees it.
- `explore/typology_grid.py` local HTML viewer, one grid per class, from the crops.
- `explore/lookaround_coverage.py` indexes Apple Look Around panoramas (no key needed).
- `explore/sam3_vs_mapillary.py` side-by-side of Mapillary's detections and SAM 3 text prompts.

All take the city name (`coruna`) and write under `data/<city>/`.

## Cluster atlas

`uv run explore/cluster_report.py coruna store_sign --source apple` builds an interactive
appearance plot, map, and crop galleries from saved DINOv2 embeddings and cluster memberships.
It uses the CPU. Open the generated `cluster_reports/dinov2/<run-id>/index.html` directly;
the map needs internet access. Use `--source gsv` once Google embeddings and clusters exist.
New DINOv2 clustering and cluster naming runs refresh the report automatically.

Each report saves `metadata.json`, `assignments.jsonl`, and `clusters.geojson`, with crop IDs,
run-scoped cluster IDs, colors, dates, projection coordinates, and position provenance.
Camera coordinates are explicitly distinguished from estimated or triangulated sign locations.
The PCA plot is a browsing projection, not the space used to calculate cluster membership.
Numeric labels and colors are not identities across different clustering runs.

`export_site.py` reads the latest `cluster_metadata_dinov2.json` and joins assignments by exact
representative crop ID. The map and wall support cluster colors and group filtering when that
metadata is present. Unmatched signs stay unassigned; old cluster coverage is never extrapolated
to newly detected signs. Imported runs retain unknown algorithm parameters rather than guessing.

## DINOv2 / DINOv3 comparison

`uv run explore/compare_embeddings.py coruna --per-source 512 --batch 8` freezes a
1,024-crop Apple/Google sample and compares the two official base-size DINO models.
The sample is reused on reruns; images are checksummed, model revisions and processors
are recorded, and inference checkpoints each batch. DINOv3 requires approved Hugging Face
access. Authentication stays in the Hugging Face credential store, outside the repository.

The comparison uses normalized CLS plus mean patch embeddings, excluding DINOv3 register
tokens, each model's official preprocessing, PCA to 50 dimensions, and identical k-means
settings. It saves raw embeddings, crop IDs, cluster assignments, neighbors, provenance,
and an interactive side-by-side report under `data/coruna/embedding_comparison/<run-id>/`.
Colors and numeric labels are specific to each model. Silhouette and agreement statistics
are diagnostics, not evidence of human-perceived quality. The viewer shows unavailable
models explicitly and can be regenerated by rerunning after access is granted.

This is an exploratory sample, not a labeled benchmark: Apple samples use existing group
representatives, Google samples are not deduplicated, and each source contributes at most
one crop per panorama. Production embeddings, clusters, and the main page remain separate
while the comparison is evaluated.

### Multi-category detection

`uv run explore/multicategory_detect.py coruna --source apple --thin 10 --workers 4` runs eleven category
proposals with fourteen separate text prompts and one SAM image encoding per view.
It starts with recent captures, reuses completed legacy store-sign predictions at the
default threshold, and writes to `data/coruna/apple/multicategory/<config-hash>/`.
Legacy crops, masks, JSONL files and completion records stay intact. `--source gsv`
supports downloaded current Google panoramas with the existing eight-view projection;
the Apple path has been GPU smoke-tested, the Google path has not yet been run.

Each view's `result.json` is an atomic completion record. Interrupted partial views
are retried. Results include source metadata, prompt, proposed category, score, box,
rectangular crop and separate mask. Same-category boxes with IoU >= 0.8 are marked
as duplicates of the highest-scoring proposal; all proposals remain saved. Different
categories are preserved for classifier review. This does not perform cross-panorama
deduplication or publish categories to the main map.

Model revision, preprocessing geometry and prompts determine the run directory.
SIGTERM/SIGINT stops after saving the current view. Runs stop before free disk space
falls below 20 GiB. `--limit 1 --cache-samples 1` exercises feature persistence on a
small sample; default runs retain features in GPU memory only. The initial sample
used 190 MB per view, making full-city disk caching unattractive.

The running service is `typology-multicategory`; inspect with
`journalctl --user -u typology-multicategory -n 20`.
The older Apple single-prompt process was suspended with SIGSTOP before migration;
its PID and saved-output counts are in `data/coruna/apple/multicategory/legacy_pause.json`.
That process has since exited; the pause file is historical metadata. Saved legacy
predictions remain available. New results use separate files.

Check conservative duplicate grouping and legacy resume filtering with
`uv run python -m unittest discover -s explore -p test_multicategory_detect.py`.

### Conservative deduplication comparison

The desired error tradeoff is to retain duplicates rather than merge distinct objects.
`OPENBLAS_NUM_THREADS=1 uv run explore/strict_dedupe.py --source apple` splits the saved
groups into groups where every pair passes independently. Repeat with `--source gsv`.
It uses existing embeddings and CPU image matching, writing proposed groups and per-pair
evidence under `store_sign/strict_dedupe_v2/`. Original groups, v1 results and map exports are unchanged.

Pairs require similarity >= 0.95, a margin over competing objects in the target panorama,
the same capture date, camera distance <= 20 m, and broad local feature agreement inside
the detection box. V2 removes camera-angle and triangulation filtering and the two-member cap.
It considers every eligible pair instead of mutual nearest neighbors. Groups join only if
every pair across the groups passes all checks, preventing chain merges. These are
uncalibrated conservative gates, not a precision guarantee.
No new cross-group matches are attempted. See the saved policy for exact thresholds.

`uv run explore/strict_dedupe_review.py` builds
`data/coruna/comparison_share/strict-deduplication-review.html`, embedding all 63 proposed
pairs from the first run plus 22 rejected examples. Decisions persist in the reviewer's
browser and can be exported as JSON. `uv run explore/strict_dedupe_review_v2.py` builds
`strict-deduplication-v2.html` in the same share directory, showing the largest and randomly
sampled v2 groups with every member visible. The first v2 run produced 784 Apple groups
with multiple observations, largest 5, and 12 Google groups, largest 3.
Check chain prevention, larger groups, deterministic grouping and local image matching with
`uv run python -m unittest discover -s explore -p test_strict_dedupe.py`.

`OPENBLAS_NUM_THREADS=1 uv run explore/wider_dedupe.py --source apple` and repeat for `gsv`.

Same-date and different-panorama constraints remain. It seeds clustering with the v2

### Scheduled updates

Two enabled user timers continue the work while SAM runs:

- `typology-ocr.timer`: up to 1,000 pending text-bearing crops per batch, then a
  30-second pause before the next batch. The worker skips completed crops.
- `typology-layer-refresh.timer`: every 15 minutes, publish changed detections/OCR.

Unit sources are in `explore/services/`. Both workers lock their outputs. The
exporter freezes inputs, skips unchanged snapshots, builds category files, then
atomically replaces the manifest. A failed export leaves the previous manifest
usable. Exported OCR ignores an unfinished trailing append. Snapshots retain at
least eight versions and all versions from the last 24 hours; this prunes only
old generated map files, never source detections, crops, OCR or review labels.

The browser checks for a new manifest every minute and offers “New data available
· Update”. Applying it preserves layer selection, search and map position. Failed
fetches retain the previous snapshot. Open inspectors are not replaced. “Snapshot
updated” uses publication time; each detection retains its image capture date.
`latest_detection_at` records result completion time, not capture time. Services
currently target Apple run `765844a02f75`; change their `--run` for a future run.

observations and evaluates a spatially concentrated sample, preserving every

The frozen 50-scene sample contains 25 randomly selected views and five each with graffiti, street-name proposals, shop signs, other categories, or no SAM proposals. It selects distinct panoramas from completed views. This is an exploratory sample, not a city-wide accuracy estimate. RapidOCR's installed text detector runs on the original perspective image and overlapping 1536-pixel tiles. Recognition and orientation classification are disabled: unreadable lettering can still produce a saved crop. The detector can also miss lettering or detect non-text patterns.

Each region retains its polygon in source-image coordinates, a padded image crop, whole-image/tile provenance, and overlapping SAM proposal IDs/categories. The detector checkpoint hash, configuration, frozen sample, source metadata, and resumable per-view records live under `data/coruna/comparison_share/street-text/`.

The review offers crops, numbered scene overlays, original-resolution images, coverage filters, optional SAM boxes, per-region text/not-text labels, and scene-level missed-text notes. Labels stay in browser local storage until exported as JSON. Generated images and reports are excluded from Git.

The first completed sample, `41a87cef15e0`, produced 880 candidate regions across 50 scenes: 547 outside SAM boxes, 80 overlapping other SAM categories, and 253 overlapping shop-sign/street-name boxes. 661 retained regions had tile-only provenance. These are detector candidates, not confirmed text counts; the whole-image and tiled passes can also split lettering differently. Visual spot-checks found additional house numbers, shop lettering and graffiti, but many false positives on windows, foliage and grilles. This baseline needs review/filtering before map publication. The 50-scene CPU pass took about 12 minutes while SAM continued running. Crop dimensions, full-resolution context files, browser navigation/filters/local review storage, and unchanged per-view records on resume were checked.

Run `.venv/bin/python explore/person_experiment.py` to resume the isolated pilot `data/coruna/apple/multicategory/8b6f53a1131e`. It reuses the frozen 50-view street-text sample, one view per panorama, and the main SAM run's pinned model revision. The sample was selected for general street variety, not to estimate person-detection accuracy. The production detector and its categories are unchanged.

The first pilot saved 45 person proposals in 16 of the 50 views. Each includes a padded full-person crop where visible, a quarter-resolution mask, source geometry, camera coordinates, capture date and full-image context. Some detections are people depicted on posters, partial/occluded bodies, or overlapping proposals. No extra classifier was added to remove them. The layer is explicitly a pilot; its dots represent capture-camera positions, not measured person locations.

`explore/export_layers.py --extra-run data/coruna/apple/multicategory/8b6f53a1131e` includes the pilot alongside the main category run. The installed 15-minute refresh service keeps this argument, so later map updates retain the People layer. Supplemental runs must have distinct categories. The existing source images, predictions and duplicate groups are preserved.

**Image capture date** in the map's layer panel filters both map and wall using inclusive From/To dates. It uses provider capture dates, not the snapshot publication time. Apple ISO timestamps retain their recorded calendar day; older records with only a month match any overlapping date range. Unknown dates are included by default and can be excluded. Filtering occurs on observations before duplicate grouping, so a matching observation can replace an out-of-range representative. Viewpoint strips then contain only the matching observations. Reset dates restores the full time range. Snapshot updates preserve the chosen filter. The legacy collection exposes only its exported representative date, so its historical member views cannot be filtered individually.

The category classifier remains a separate, optional evaluation stage intended to catch incorrect SAM category proposals. Its small evaluation predictions are not automatically applied to map layers, and it is not part of the People pilot.

### Map navigation and downloads

The map has a thumbnail panel for the current area. Click a numbered point to
browse its objects, or a thumbnail to inspect crops and viewpoints while keeping
the map visible. Share view saves the map position, filters and selected object in
the URL. Browser Back restores previous selections. Street and satellite basemaps
are available from the map control.

Filter by category, source, capture year, text and barrio. Barrio membership uses
the municipal **Barrios / AA VV** polygons at the record's displayed coordinates.
For SAM observations these are camera coordinates, so an object across a barrio
border can be assigned to the camera's barrio. Points outside all polygons remain
unassigned. The council's names are retained, including port and industrial areas.
Refresh the checked-in boundary snapshot with `uv run explore/fetch_barrios.py`.
Attribution and the source URL are saved inside `site/barrios.geojson`.

Download selection exports CSV, GeoJSON or JSONL. The duplicate-group toggle
selects object-group records or individual observations. Group records include
member IDs and the retained observations. Category, source, date and barrio filters
apply before grouping; text searches the retained group views. Only this map area
restricts the export and wall to the displayed representative positions. Clicking
a map point narrows the thumbnail panel only; downloads still use the filters.

GeoJSON includes an export manifest. CSV and JSONL have a separate Manifest
download with the filters, snapshot, model information, boundary source and counts.
CSV nested fields contain JSON; spreadsheet formula prefixes in strings are
escaped. Image URLs refer to existing viewer assets; images are not bundled, and
these exports do not grant rights to provider content.

The frontend is `site/index.html` plus `site/app.js` and `site/barrios.geojson`.
`export_site.py` copies all three along with the method page.
